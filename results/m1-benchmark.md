# M1 benchmark — MobileCLIP-S0 photo search

_COCO Karpathy test split, first 1000 photos, 5000 captions. Laptop CPU (Apple M-series), ONNX Runtime 1.31.1, 4 threads. Generated by `./gradlew :bench:run`._

## Search accuracy and speed

| Models | Size on disk | Image → vector | Text → vector | Found in top 1 | top 5 | top 10 |
|---|---|---|---|---|---|---|
| full size (fp32) | 215 MB | 14.4 ms | 4.7 ms | 61.6% | 87.2% | 94.4% |
| quantized (uint8, downloaded) | 54 MB | 44.7 ms | 3.7 ms | 0.1% | 0.3% | 0.9% |
| our int8 text + full-size images | 176 MB | 13.1 ms | 2.9 ms | 61.6% | 87.2% | 94.4% |
| downloaded uint8 images + full-size text | | | | 0.1% | 0.3% | 0.8% |

Image decode + resize + crop in Kotlin: 11.0 ms per photo.

Our Kotlin resize vs the official Python (PIL) preprocessing, 50 photos: same direction 0.9986 on average (worst 0.9893; 1 = identical).

## Index: HNSW vs checking every photo

| Index | Matches brute-force top 10 | Time per search |
|---|---|---|
| check every photo | 100% | 0.231 ms |
| HNSW ef=16 | 99.3% | 0.063 ms |
| HNSW ef=64 | 100.0% | 0.152 ms |
| HNSW ef=200 | 100.0% | 0.304 ms |

With only 1000 photos, checking every one is already fast; HNSW pays off at tens of thousands.
